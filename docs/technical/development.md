# Development Guide

## Prerequisites

- Node.js 24 is recommended, matching the currently installed types;
- Yarn Classic, because the repository uses `yarn.lock` and Yarn 1 workspace syntax.

Versions are not yet pinned through an `.nvmrc`, `.node-version`, or `packageManager` field. If
reproducibility becomes a concern, formalize this choice in a decision record.

## Installation and execution

From the repository root:

```sh
yarn install
yarn dev:back
```

To use a different port:

```sh
PORT=4000 yarn dev:back
```

Development mode reloads the backend with `tsx watch`. Local production mode uses:

```sh
yarn workspace @cowish/backend build
yarn workspace @cowish/backend start
```

## Checks

```sh
yarn lint
yarn format:check
yarn test
yarn build
```

Backend tests are located in `apps/backend/test`. They open the server on an ephemeral port and
query the API through `fetch`.

## Adding a backend route

1. Define the contract: method, path, inputs, responses, and errors.
2. Confirm the rules in the product context and identify any remaining assumptions.
3. Validate received parameters, query values, and request bodies.
4. Extract business logic from the handler when it goes beyond simple orchestration.
5. Add tests covering at least success, invalid inputs, and relevant permissions.
6. Update the API contract documentation.

## Conventions

- Use ESM imports with the `.js` extension in TypeScript code compiled through `NodeNext`.
- Avoid `any`; treat caught errors as `unknown`.
- Return consistent HTTP statuses and JSON bodies.
- Do not expose internal information in public error messages.
- Use root-level scripts to keep local and CI checks consistent.
- Do not edit `dist` manually: it is generated by the build and ignored by Git.

## Environment variables

The only variable currently recognized is:

| Variable | Required | Default | Description       |
| -------- | -------- | ------- | ----------------- |
| `PORT`   | No       | `3000`  | Backend HTTP port |

When adding a variable, document its behavior and add a placeholder value to `.env.example`.
Never include a real secret there.
